grc-program

A GRC program as a git repository. The control inventory is the system of record — frameworks, the trust center, and every OSCAL package are projections. This page is how you run the public template, and how you take a private copy into your own organization before any real evidence lands.

What it does

Most GRC tooling treats a control as a document: a policy PDF, a questionnaire answer, a screenshot of a settings page. This repository treats a control as a record you can query. Every framework requirement, scenario, policy paragraph and piece of evidence is a foreign key to a control_id. Nothing else is first-class.

The pipeline lands source state time-indexed (so a shrinking denominator cannot look like an improving pass rate), asserts every control against a fully enumerated population, routes new failing subjects as work, and drafts a ticket body without posting it. A human gate records consent. Consent is not a merge. Live send stays off until a named contract is confirmed against the sink you actually use.

Output is an OSCAL package with deterministic v5 UUIDs, a four-direction gap assessment, control-health as a classification (not a score), and FAIR-CAM math that refuses an unlabelled number. Agents may pack context and draft. They do not evaluate control efficacy, and they do not write the inventory on a shared branch.

When and where to use it

Use it when

  • You are standing up a GRC program and need a system of record you own, not a platform you cannot read from.
  • You want evidence that is a query against a population — total, a fully enumerated failing[], a coverage basis — not a screenshot.
  • You need machine-readable artefacts an assessor can re-run: OSCAL that re-exports byte-identically, a warehouse you can open on a past date.
  • You want a GRC engineer to practice the discipline: a ticket is draft, a gate records consent, a human merge is the control.

Do not use it when

  • You need a hosted dashboard on day one. This is a CLI and a git repository. The demo writes files. Nothing is a SaaS.
  • You want the model to decide that a control works. Efficacy is a named human with a confidence tier. That refusal is the product.
  • You need a finished CMMC, FedRAMP 20x, or AI-probe program. Those are cui-control-plane, ksi-harness, and proofplane. This repo is the general program.
  • You plan to commit real evidence to a public fork. That is the one thing this page exists to stop.

How to use it

Node 22+. No API key, no cloud account, no spend. Nothing contacts a real system. Windows, macOS and Linux. On Windows, read docs/SETUP.md first — line endings are a correctness issue here, not cosmetics.

1. Clone and confirm the suite.

git clone https://github.com/RootCawsLLC/grc-program.git
cd grc-program
npm ci
npm test
npm run validate
npm run baseline

npm ci runs the prepare hook that pins git identity. Do not skip it: a tree that skipped install commits under whatever git infers. The first baseline looks bleak — seed controls, almost none instrumented, a long gap list. That is the shape of the output, not the state of any company. None of those records are yours yet.

2. Run the synthetic pipeline end to end.

npm run demo

Three fixture cycles land, the denominator holds, variance is decomposed into the three FAIR-CAM segments, and OSCAL assessment results write under out-synthetic/ stamped NOT REAL EVIDENCE. Section 5 of the demo is the latest cycle: one continuing subject, no new ticket. Section 6 walks the previous cycle — the one that actually had something new — and prints draft save_issue bodies. posted=false. executed=false. That is the whole argument in one run.

3. Read one control end to end. Open a file under controls/. The record has an owner, a population definition, a primary FAIR-CAM function, and framework identifiers — never framework text. Then run the pieces the demo already chained:

npm run collect -- --fixture
npm run assert
npm run drift
npm run route -- --dispatch --pack --draft

New subjects become events. Continuing subjects stay silent. Packs hydrate from the read-only MCP tools into one file per specialist. Drafts sit next to those packs. Nothing is posted. --live is a refusal.

4. UAT the collectors against dummy sources before connecting a live tenant.

npm run sandbox

--sandbox is a third mode, not a fallback from live collect. It runs the collectors against official-format IAM credential-report CSV, dummy GitHub repos (RootCawsLLC/sandbox-uat-*), a file IdP, and an HRIS inbox CSV. Everything is stamped NOT REAL EVIDENCE. --sandbox and --fixture cannot be combined. Live collect still refuses without credentials, and still refuses with them until a live client is wired.

5. Useful commands once you have run it once.

npm run health          # classification, not a score
npm run gap -- --direction remediation
npm run emit            # the OSCAL package; re-run is byte-identical
npm run simulate        # FAIR Monte Carlo; refuses uncalibrated scenarios
npm run orchestrate -- --event fixtures/events/risk-acceptance.json
npm run gate -- --list
npm run mcp             # eight read-only tools over the control graph

A risk-acceptance event without a named per.* actor and an expiry is refused. A Slack or GitHub click can decide a stored gate only after HMAC verification and an identity map from a platform user id to that per.*. There is no HTTP listener. Usernames and logins are not identity.

Public template, private instance

This repository is public so you can see the machinery, run the fixtures, and copy the shape. It is a template, not a hosted program. Real inventory, extracted findings, exceptions, and warehouse rows name accounts, roles, and failing people. Those do not belong on a public remote.

  1. Use it as a GitHub template, or fork it. Either produces a repository you own. The public original stays the template. Your copy is the instance.
  2. Keep the copy public while it is still fixtures. Run npm test and npm run demo. Read the ADRs. Nothing in fixtures/ is evidence, and the stamp is designed to travel into every artefact generated from it. Do not strip the stamp to make a demo produce a nicer number.
  3. Set the copy private before any real data lands. Do this before the first real control YAML, the first extracted finding, the first exception, and the first non-fixture collect. GitHub: Settings → General → Danger zone → Change repository visibility. A public instance that later “just has one real row” is already a leak.
  4. Never commit real evidence. out/, out-synthetic/, .warehouse/, .evidence/ and intake/source/ are gitignored. Audit reports are NDA-gated and stay on disk, not in git. Generated output overwrites without asking — redirect or back up before a trial run against anything you care about.
  5. Replace the seed, do not decorate it. The shipped controls, scenarios and identity map are worked examples. Your control_ids, owners, populations and per.* roster are yours. Do not invent Slack or GitHub mappings for people who are not on that roster.
  6. Leave live send off until you have confirmed the sink contract against the real UI and named the credentials. A silent no-op send is forbidden; an unconfirmed send is a throw. Same for an HTTP listener: verification is a function so a half-wired server cannot become first inbound.
The public repo is the template. The private fork is the program. If you are deciding which of those you are looking at, and the remote is still RootCawsLLC/grc-program, you are on the template. Do not open a PR that adds your evidence here.

Take it into your organization

You do not clone this onto a shared drive and call it the GRC function. You take the rule and the shape.

  1. Controls are the substrate. A risk register is an inventory of control gaps. An incident is a control failure that produced harm. A policy is a written expectation about a control. Split by layer when owner, cost, threat model or failure mode differs. Platform IAM, enterprise SSO, in-product authz and customer SSO are four controls, not one “Access Control.”
  2. Policy last. Build the control, instrument it, observe it holding, then generate the policy from the record. Guard G2 fails the build on a policy for a control that is not operating.
  3. Populations, not samples. Every test returns total, a fully enumerated failing[], coverage_basis and query_ref. A pass rate that “improved” because the denominator shrank is a failure of the asset inventory.
  4. Time-index everything. If the landing layer overwrites, the pipeline is a dashboard and Variance Duration is unreachable.
  5. Label every number measured, derived, calibrated-estimate or assumed. An unlabelled number is rejected. A range with no provenance and a range with six sourced parameters must not look equally authoritative.
  6. A pull request is the only path to normative. Nobody writes controls/, policies/ or exceptions/ on a shared branch. A human merges. The merge is the control, and it is reviewable as a diff.
  7. No agent evaluates control efficacy. A probe may run and record what happened. Efficacy is a relationship between control state, threat behavior, asset value and compensating controls. The training data to learn it does not exist. A fluent answer here is the most dangerous possible output, because it is indistinguishable in form from a correct one.

If this is week one of a real program, docs/SOP-DAY-ONE.md is the checkbox procedure. BUILD-ORDER.md is the remaining units. docs/adr/ is why the machinery is shaped this way. This page is the operator’s entrance.

Honest limits

Read the status honestly. The seed inventory is a worked example, not your program. Fixture runs stamp every artefact NOT REAL EVIDENCE. Collectors are written against API shapes and have not been run against a live tenant. Live Slack, GitHub and Linear send is a refusal until a contract is confirmed; a confirmed send still leaves executed false. There is no HTTP listener. Scenario parameters ship as assumed at confidence tier 1; filling them with a plausible range is the failure mode FAIR exists to prevent. Framework identifiers only — no normative text from any standard. The full working agreement is CLAUDE.md.
